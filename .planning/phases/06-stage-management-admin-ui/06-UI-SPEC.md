## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, color swatch size |
| sm | 8px | Compact element gaps within rows |
| md | 16px | Default padding inside modal container |
| lg | 24px | Section spacing between stage list and form |
| xl | 32px | Modal header padding |
| 2xl | 48px | Page-level spacing (not used in this modal) |

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `n-slate-1` / `n-slate-2` | Modal background, stage list rows |
| Secondary (30%) | `n-alpha-3` (overlay modal container) | Card-style rows, form backgrounds |
| Accent (10%) | `n-brand` (#2781F6) | Manage Stages button, Save button, interactive highlights |
| Destructive | `n-ruby-9` | Delete stage button, delete confirmation |

**Accent reserved for:**
- "Manage Stages" button in LeadsIndex header
- Primary action buttons inside modal (Create Stage, Update Stage)
- Active/focus ring on interactive elements

**Destructive reserved for:**
- Delete stage button (icon only, ruby ghost)
- Delete confirmation dialog header/icon

**Notes:**
- Chatwoot color tokens use `n-*` prefix (n-slate-*, n-alpha-*, n-brand)
- Modal backdrop: `n-alpha-black2` with `backdrop-blur-[4px]`
- Border: `n-weak` for subtle dividers between rows

## Component Inventory

### StageManagementModal.vue
**Type:** Full modal dialog
**Behavior:** Right-aligned full-height panel (`modalType="right-aligned"`)
- Opens via `v-model:show` from parent
- Contains: stage list + create form header
- Width: 30rem (w-[30rem])
- Close on: backdrop click, Escape key, X button
- Slot: full control over interior layout

### Stage List (inside modal)
**Type:** Vertical card-style list
**Layout per row:**
```
[Color swatch 24x24] [Stage name]                    [Up button] [Down button] [Delete button]
```
- Color swatch: `rounded-md size-6` with stage color background
- Stage name: `text-sm font-medium text-n-slate-12`
- Up/Down buttons: `Button` ghost slate, icon-only (i-lucide-arrow-up, i-lucide-arrow-down)
- Delete button: `Button` ghost ruby, icon-only (i-lucide-trash-2)
- Row: `flex items-center gap-3 px-4 py-3 bg-n-alpha-3 rounded-lg`

### Create/Edit Stage Form (dialog)
**Type:** Modal dialog (centered) opened from "Add stage" button or row click
**Fields:**
- Stage name: `input` with `n-slate-11` placeholder, `n-slate-12` text
- Color: `ColorPicker.vue` with Chrome picker
- Default color: `#6B7280` (gray-500)
**Buttons:**
- Save: `Button solid blue` label="Save"
- Cancel: `Button ghost slate` label="Cancel"

### Delete Confirmation Dialog
**Type:** Centered modal (not right-aligned)
**Layout:**
- Title: "Delete stage?" — `text-base font-semibold`
- Body: warning message about unassigned contacts
- Actions: Cancel (ghost slate) + Delete (solid ruby)

### Manage Stages Button
**Type:** Header button in LeadsIndex.vue
**Visibility:** Admins only (`useAdmin().isAdmin`)
**Style:** `Button outline slate` with icon (i-lucide-settings)
**Placement:** Right side of leads page header bar

## Interaction Contract

### Optimistic Updates
All stage operations (create, edit, delete, reorder) update UI immediately via `usePipelineStore`:
1. Update local state immediately
2. Call API action
3. On failure: revert state + show toast via `useAlert()`

### Reorder Flow
- Up button: disabled when stage is at top (position = 0)
- Down button: disabled when stage is at bottom
- Click calls `pipelineStore.moveStage(stage.id, 'up' | 'down')`
- Store action calls `PipelineStagesAPI.move(id, direction)`

### Delete Flow
1. Click delete icon on row
2. Confirmation dialog opens (centered modal)
3. On confirm: optimistic remove from list + API call
4. On failure: revert + toast error

### Edit Flow
1. Click stage row (not delete button)
2. Edit dialog opens with pre-filled name + color
3. Save updates via `pipelineStore.updateStage(id, data)`
4. Cancel reverts any optimistic changes

### Create Flow
1. Click "Add stage" button at top of list
2. Create dialog opens with empty fields + default color
3. Save creates via `pipelineStore.createStage(data)`
4. New stage appended to bottom of list
